# 工程决策记录

## ADR-001：技术栈与项目范围

- 日期：2026-10-22。
- 来源：项目负责人在本次初始化任务中明确选择Spring Boot+Vue3+MySQL，并确认通用模板适用。
- 决定：一个仓库管理前后端、数据库、Docker配置和协作文档；后端采用Java21/Maven开发环境，前端采用Node22/npm开发环境，数据库采用MySQL8.4。
- 当前范围：应用部分只创建文件夹及`.gitkeep`，不生成业务代码、构建清单和数据库表。
- 后续：创建应用时固定Spring Boot、Vue及其他依赖的具体版本，提交对应构建文件和前端锁文件。课程资料未规定这些版本，本记录不将其表述为课程要求。

## ADR-002：接口公共契约

- 日期：2026-10-22。
- 决定：统一`/api/v1`前缀、JSON/camelCase、字符串ID、RFC3339时间、分页方式和响应结构，使用OpenAPI3.0.3维护公共类型。
- 原因：当前可以确定传输约定；业务路径、角色、状态和字段仍需需求分析。
- 后续：业务接口经评审后加入OpenAPI，不以示例路径冒充已确定接口。

## ADR-003：开发容器与源码初始化解耦

- 日期：2026-10-22。
- 决定：Compose提供MySQL、Swagger UI、Maven/JDK和Node/npm环境；前后端容器保持待命，通过`docker compose exec`运行工具及后续应用命令。
- 原因：当前没有`pom.xml`和`package.json`，直接执行应用启动命令必然失败。
- 后续：业务开发阶段初始化应用并验证后，再评审是否改为自动启动开发服务器。环境配置不代表应用已实现。

## ADR-004：项目范围、分工及课程排期

- 日期：2026-10-24。
- 来源：项目负责人确认的范围与分工，以及本次补充的教师课程进度计划表；原内部排期据此修正，正式计划见[项目计划书](plans/project-plan.md)。
- 范围：单驿站双端、本地Docker演示；学生、工作人员、管理员三类角色；核心收发流程、拒收与退件、取消寄件和简单统计，含账号、权限和必要的基础信息管理。
- 组织：5人共同开发，每人每周10～12小时；项目负责人杨振煜承担项目管理、公共框架与集成，任奕阳（A）负责收件与退件，张海睿（B）负责学生查询、取件与拒收，沈翔宇（C）负责寄件与取消，戴靖桓（D）负责统计与系统测试统筹。姓名与代号对应关系已由项目负责人确认，任务登记统一使用姓名，学号按正式课程材料登记。
- 排期：项目实施第6～17周。第6周10-22分组、计划与调研，第7周10-29提交计划，第8周11-05提交业务流程，第9周11-12提交数据分析，第11周11-26提交功能分析与原型，第12周12-03提交系统设计，第13周12-10提交数据库设计，第14周12-17提交详细设计，第14～15周编码，第16周12-31测试并提交测试用例及项目分析总结报告，第17周01-07继续测试并答辩。团队内部安排第14周贯通首条流程、第15周全量联调，不作为教师额外要求。按每人每周10～12小时、5人共12周重算预算为600～720人时。
- 质量：全部计划功能逐项验收，检查核心正常与异常流程、权限及数据保存；阻断业务或造成数据错误的问题修复并复测后交付。
- 监控：每周两次20～30分钟短会，周末汇总周报，第5～15周共11份；每人负责本模块需求、设计、开发、测试和文档，计划书明确汇总职责。
- 延期：保留确认的业务范围，先简化页面、统计展示和操作细节，暂停新增需求并调整人手，保留测试与演练时间；范围变化另行确认。
- 后续：第6周启动调研，第7～10周逐步确认操作权限、拒收与退件交接、取消条件和统计指标，第11周提交功能分析及原型前完成确认；第11～13周形成并评审业务接口与数据设计。本次仅编制文档，不新增业务实现或接口端点。此项保留2026年10月24日的计划，后续取件方式及规则确认进展见ADR-005。

## ADR-005：跨文档分工统一与自助取件确认

- 日期：2026-10-26。
- 来源：项目负责人要求核对整个项目的成员模块与文档一致性，并明确选择“学生自助核验，由系统确认取件”。
- 决定：学生输入取件码和收件手机号后四位，由系统结合当前业务条件校验，通过后确认出库；工作人员不执行取件核验或确认。此前工作人员核验取件的表述由本决定替代。
- 分工：REQ-001杨振煜负责公共框架、账号权限、基础信息与系统集成；REQ-002任奕阳负责收件入库与退件；REQ-003张海睿负责个人查询、自助取件、拒收与撤回；REQ-004沈翔宇负责寄件申请、受理、寄出与取消；REQ-005戴靖桓负责统计。五人继续负责各自模块的前端、后端、数据、需求设计、测试和文档，材料汇总职责沿用计划书。
- 当前依据：调研报告已记录账号关联、拒收退件、寄件取消、管理员权限和七项统计指标等项目规则；尚未开展访谈和现场观察。后续需求材料按已确认规则细化，不把规则确认当作业务实现或运行验证。
- 同步范围：团队分工、项目计划Markdown及DOCX、调研报告、周报、协作规范、接口说明、架构与验收说明。历史周报的会议事实及逐人工作保留，新增确认以修订说明列明。
