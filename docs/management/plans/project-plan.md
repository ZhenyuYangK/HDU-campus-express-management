# 校园快递收发系统项目计划书

## 项目概况

本项目为杭州电子科技大学软件工程课程设计项目，建设单驿站双端校园快递收发系统。学生端支持个人查询、自助核验取件、拒收与撤回及寄件申请；工作人员端承担驿站收件、寄件与退件处理，同时提供管理员使用的账号、权限及基础信息管理功能。系统采用Spring Boot+Vue3+MySQL，使用Docker在演示电脑本地运行，通过不同账号展示三类角色的操作。

项目实施周期按教师进度表安排为第6～17教学周，共12周，从10-22分组、项目计划和调研推进至次年01-07项目答辩。周报按课件另列的第5～15周提交，共11份。团队由项目负责人杨振煜和任奕阳（A）、张海睿（B）、沈翔宇（C）、戴靖桓（D）共5人组成，均参与开发，采用业务模块分工。每人每周计划投入10～12小时，包含开发、会议、评审、测试和文档；按12周计算，总计划投入600～720人时。成员姓名与代号对应关系已确认，学号按正式课程材料登记。

第6周分组、编制项目计划并调研；第7周提交项目计划，第8周提交业务流程分析，第9周提交数据分析，第11周提交功能分析与界面原型，第12周提交系统设计，第13周提交数据库设计，第14周提交详细设计；第14～15周编码，第16周测试并提交测试用例与项目分析总结报告，第17周继续测试并答辩。具体日期和两段课时的安排见逐周计划。

当前仓库具备工程目录、协作规范、公共接口约定和Docker配置，前后端业务目录仍为占位结构。本计划安排后续需求、设计、开发和验收工作；任务实际进展在[团队分工与任务登记](../team.md)维护。

## 项目目标与范围

### 角色和使用范围

| 角色 | 业务范围 | 权限验收重点 |
| --- | --- | --- |
| 学生 | 办理个人查询、自助核验取件、拒收与撤回及寄件申请 | 只能访问本人获准查看和办理的业务 |
| 工作人员 | 执行驿站收件、寄件受理与寄出、退件及业务纠错 | 只能执行授权的驿站业务操作 |
| 管理员 | 额外管理账号、权限和必要的基础信息 | 管理操作与普通业务操作的权限边界清楚 |

双端指学生端与驿站工作人员端，管理员通过授权的管理功能操作。第一版建设范围限定为单驿站、本地课程演示，开发任务以以下五组需求为依据。

## 质量要求与验收安排

### 功能与权限验收

全部REQ-001～REQ-005逐项演示和检查。核心收发流程覆盖正常与异常情况，核对学生个人数据访问范围、工作人员业务权限、管理员管理权限以及保存后的数据。任奕阳、张海睿联合核对拒收、退件和取件之间的处理衔接；沈翔宇核对寄件申请、受理、寄出与取消的规则；戴靖桓使用同一批业务记录核对统计结果。

阻断业务流程、造成数据错误或破坏已确认权限边界的问题，须由所属模块负责人修复并复测后交付。其他遗留问题记录影响、责任人和后续安排，由项目负责人组织判断是否影响验收。测试记录包含用例、环境、预期、实际表现、结果和证据，未执行项说明原因。

代码修改先由模块负责人验证，再经其他成员评审；公共接口或数据结构变更同步更新OpenAPI、设计与相关用例。测试使用可公开的合成数据，本地演示按学生、工作人员、管理员账号分别检查，重启应用后复查已保存业务数据。

## 执行监控与变更管理

每周组织两次20～30分钟短会，分别检查开发进展和联调问题，周末汇总周报。成员会前更新任务实际状态、交付物、验证结果及阻塞；杨振煜协调接口、跨模块问题和人手安排，戴靖桓跟进测试问题，会议结论写入当周周报。

每项任务登记主责、需求、依赖、计划完成周、验收条件和实际证据，状态使用“待开始、进行中、待评审、待验证、完成”。进度以实际交付物及验证情况判断，不用代码行数或主观百分比代替完成条件。周报逐人说明工作，记录延期原因、集中讨论结论和下周重点。

需求调整由提出人说明原因、涉及功能及对接口、数据库、开发、测试和材料的影响，项目负责人组织受影响成员评估并确认。经确认后同步需求、OpenAPI、设计、用例、任务表和周报。第14～15周编码与联调落后时，先暂停新增需求，简化页面表现、统计展示和操作细节，在保留已确认业务行为和验收标准的前提下重新分配人手，保留第16周测试与材料提交、第17周继续测试及答辩的时间。业务条件、权限或异常处理的删减不属于页面简化，须作为范围变更另行确认。

每个模块的前后端改动使用同一业务契约；任务分支和PR执行[团队协作规范](../../collaboration.md)。公共框架和公共数据变更由负责人协调，模块负责人维护各自实现和用例。开发问题可按需在本机保留，团队共享问题由成员在周报、PR或Issue中手动总结。
