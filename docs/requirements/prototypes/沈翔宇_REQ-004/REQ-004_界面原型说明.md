# REQ-004界面原型说明

负责人为沈翔宇，版本日期为2026-11-23，材料待评审。

浏览器打开[交互原型](REQ-004_界面原型.html)。顶部导览可按原型编号切换样例，也可在同一组演示记录中切换角色，查看同一申请的办理结果。源码由HTML、[样式](prototype.css)和[脚本](prototype.js)组成，复用[REQ-001公共样式](../杨振煜_REQ-001/prototype.css)与[校园驿站品牌](../../../design/assets/campus-delivery-station.svg)。学生端沿用REQ-003的侧栏、列表与确认对话框。工作人员和管理员沿用REQ-002的工作台布局，办理表单采用右侧抽屉。

课程汇编见[REQ-004界面原型设计DOCX](REQ-004_界面原型设计.docx)。需求依据见[功能分析配套说明](../../function-analysis/沈翔宇_REQ-004/REQ-004_功能分析配套说明.md)、[寄件数据分析表](../../data-analysis/沈翔宇_REQ-004/REQ-004_寄件数据分析表.xlsx)、[共享数据定义](../../data-analysis/shared-data-dictionary.md#寄件状态转换)与[业务流程01～08](../../business-flows/沈翔宇_REQ-004/)。

## 字段与展示

| 界面内容 | 数据项 | 原型处理 |
| --- | --- | --- |
| 申请编号、当前账号、角色、寄件状态、提交时间 | DATA-004-01、03、11，DATA-001-01、05 | 申请编号和提交时间由演示系统生成，归属取提交账号。状态采用共享登记中的四种中文显示值。账号及编号按文本保持原值。 |
| 寄件人姓名和手机号、收件人姓名和手机号、收件详细地址、物品说明 | DATA-004-05～10 | 六项必填。两个手机号演示中国大陆11位手机号校验。错误提示显示于对应字段下。申请中的联系号码用作业务联系。 |
| 状态、提交日期范围、关键词 | DATA-004-12～14 | 可选。演示按单个状态、含起止日的提交日期与申请编号或运单号组合筛选，日期须成对且起始不晚于结束。按提交时间倒序，时间相同时按编号排序。列表每页20条，返回清单保留筛选和页码。 |
| 办理前状态、受理人及受理时间、公司及运单号、寄出办理人和完成时间 | DATA-004-04、16、18、20，DATA-001-01、11 | 抽屉显示办理前状态。快递公司选项采用REQ-001维护清单的合成快照。运单号按文本录入并保留前导零。办理人取当前账号，受理与寄出各自记录成功时间。 |
| 取消方式、操作人、时间、原因 | DATA-004-21、23、24，DATA-001-01 | 成功时根据角色和原状态记录取消方式。学生无需填写原因，工作人员演示选填。已填写的原因显示于工作人员详情。 |
| 更正人、时间、原因、说明、完成判断及原内容 | DATA-004-26～30，DATA-001-01 | 原型以收件详细地址展示未完成记录的更正方法。原因必填，完成记录的说明必填。工作人员可查看更正留痕，完成事件与追加说明分开显示。 |

时刻按UTC+08:00显示为`yyyy-MM-dd HH:mm:ss`。详情仅显示已发生的事件。管理员界面采用较少的可见字段，学生本人和工作人员详情展示合成联系方式。联系人、地址与更正留痕的正式可见范围仍按P004-08评审。

## 演示路径

- 从UI-004-01填写合成数据，提交后得到`APP-DEMO-006`。用导览栏切换到工作人员，打开同一申请受理，再登记寄出。切回学生，可在本人详情看到同一申请的公司、运单号及完成时间。
- `APP-DEMO-001`用于核对受理、学生自主取消和未完成更正。已受理的`APP-DEMO-002`用于寄出或工作人员取消。`APP-DEMO-003`为已寄出记录，用于查看进展、取消限制和追加说明。选择导览编号会重新载入该场景的初始样例。
- 导览中的「查询加载中」「查询无记录」「查询请求失败」「无访问权限」用于查看列表反馈。「保存请求失败」令下一次有效提交暂时失败，表单保留输入，可再次提交。
- 演示状态冲突时，先关闭预设抽屉或对话框，选择「确认前状态已变化」，再从详情进入操作。确认时模拟另一方先成功，详情显示最新状态。未完成更正遇到申请已寄出时，旧输入无法覆盖记录，可从详情进入「追加说明」。
- 普通对话框及抽屉支持关闭按钮、Escape和点击遮罩，关闭后焦点回到触发按钮。处理中禁用表单操作，成功后刷新当前详情。

P004-01～10的未决项以[功能分析配套说明](../../function-analysis/沈翔宇_REQ-004/REQ-004_功能分析配套说明.md#待评审事项)为准。原型中的筛选、取消原因可选、地址更正和字段可见性是评审样例。业务接口、operationId、Schema、错误码及事务细节待设计。寄出量与取消量按各自成功事件时间交接REQ-005，追加说明沿用原完成事件。原型在浏览器内运行，数据为合成样例。
