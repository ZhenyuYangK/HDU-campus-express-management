# 界面原型团队规范

## 依据与交付

开始前读取[团队进度](../../management/team.md)、[全过程规范](../../standards.md)、[功能分析规范](../function-analysis/README.md)、对应功能和数据分析，以及[前端设计规范](../../design/frontend-design.md)。涉及调用时同时读取[接口规范](../../api/README.md)和[OpenAPI](../../api/openapi.yaml)。

各模块负责人完成本模块原型，张海睿协调双端交互一致性。保存于本目录的`姓名_REQ-编号/`，保留可编辑源文件及导出图片；每个功能项至少有对应的一张原型图片，图片汇入课程DOCX，执行[CR-04](../../course-requirements.md)。共享页面可复用同一原型，但每个功能项须明确图片及其入口、操作区域，必要时补充状态图。

## 原型必须表达的内容

| 内容 | 要求 |
| --- | --- |
| 标识与关系 | `UI-<三位需求序号>-<两位流水号>`、页面名、角色、功能编号及版本日期 |
| 页面结构 | 入口、导航、布局、返回和下一步；双端共用功能保持一致的业务含义 |
| 数据 | 字段中文标签与数据项编号，列表列、详情、表单、格式及可见范围 |
| 输入 | 必填、只读、默认值、格式限制及字段错误位置，规则引用数据分析 |
| 操作 | 按钮触发条件、调用功能、成功反馈及后续页面或数据刷新 |
| 页面状态 | 正常、加载、无数据、输入错误、请求失败及无权限等适用状态；无需独立图片的用注释说明 |
| 业务条件 | 当前条件下允许、禁用或隐藏哪些操作及原因，结果与功能定义一致 |
| 调用映射 | 有接口时引用operationId与字段映射，尚未设计时标注待设计，不能虚构已可调用的地址 |

原型显示文案可以使用统一中文名称，JSON字段仍按契约；在说明中建立标签与字段映射。原型需要新增输入、状态或权限时，先回到功能与数据分析确认，不能让绘图结果自动成为需求。

## 公共界面与交互统一

1. 字体、层级、间距、动效及组件遵循前端设计规范。原型中尚未落实的字体资源和实现能力按实际标注，静态原型不能证明字体加载或交互已通过。
2. 登录入口、导航、表单布局、查询条件、列表分页、对话框、错误及成功提示等公共模式，由张海睿协调形成共用样式或原型组件，各模块复用；具体组件库仍按初始化时的统一选型接入。
3. 相同动作沿用同一用语和反馈方式，状态展示引用同一数据定义；不为同一流程分别设计冲突的角色操作。
4. 分页与筛选遵循接口规则；ID、单号和核验标识保持原值及前导零。页面时间展示与接口时间转换须说明，不能展示一个格式就推定接口按该格式传输。
5. 根据功能说明处理提交中、失败重试和重复点击的反馈；是否允许重试及重复请求的业务结果由接口与详细设计确认，页面禁用不能代替后端约束。
6. 权限控制同时考虑入口和数据展示，样例使用合成数据；页面隐藏操作与后端权限校验分别验收。

## 评审与交接

逐功能核对原型图片、角色、字段、输入限制、正常及异常反馈，检查可从入口走完对应流程。张海睿核对公共样式和双端交互，各模块与后端及数据维护方核对输入输出。

导出后检查文字、控件与长标识是否可读，DOCX中的图片和编号是否齐全，源文件与图片是否一致。原型评审与实际页面验收分别记录，原型图不作为运行截图；确认结果和待办更新团队进度，清理本次临时预览等中间文件。
