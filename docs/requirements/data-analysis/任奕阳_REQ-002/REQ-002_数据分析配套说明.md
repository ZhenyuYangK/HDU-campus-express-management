## 三、与REQ-003的分工

1. 拒收申请、拒收原因、拒收时间、拒收处理状态、撤回时间与撤回结果**全部由REQ-003维护**，本表只引用编号与状态，不复制其值，避免同一业务事实两处可改。
2. 学生成功提交拒收时，REQ-003即暂停取件并使包裹进入拒收待退件；工作人员核对不是暂停的前置条件。本表保留“拒收核验信息”候选数据类，工作人员后续核对与退件交接不延迟既有暂停时点。通过／驳回及驳回原因继续以P002-04挂起；候选驳回不等同学生撤回，不据此自动恢复取件，评审后再同步处置规则。
3. 包裹状态五个取值（待取件／已取件／拒收待退件／退件中／已退件）两模块共用，任何一方修改须同步另一方与共享登记。
4. 取件时间复用REQ-003原表DATA-003-09，REQ-003核验通过并确认出库成功时记录，REQ-002包裹主记录及REQ-005读取同一成功事件；核验失败或未出库时不填。包裹主记录和取件记录的物理映射待设计，不代表两处分别写入可变时间。
5. 学生拒收来源的退件须引用当前有效拒收申请；人工异常退件可以没有拒收申请编号，不补造请求。包裹待关联时，归属账号、关联方式和关联建立时间允许缺失，建立关联成功后再记录实际值。
