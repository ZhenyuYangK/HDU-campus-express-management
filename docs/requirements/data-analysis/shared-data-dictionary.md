## 场景与展示规则

现有分析材料为REQ-001、REQ-003、REQ-004三份XLSX及本登记，不新增模块配套文件。完整说明直接写入各份XLSX“数据项”J列及“数据类”BG列；材料负责人、更新日期、状态位于各表BG2。编号复用、业务角色与来源、合成例、待评审事项均可在原表定位。具体业务Schema、DTO、前端类型和物理表列均待设计。

REQ-001账号、姓名、绑定手机号、角色及强制改密标记按各自场景必填；普通改密需要原密码，强制改密不要求原密码。密码原文不持久保存，原文和哈希不作为业务查询返回字段。账号创建和手机号变更由管理员核对办理；变更手机号不自动迁移历史包裹。账号姓名、绑定手机号与业务联系人、完整收件手机号及取件核验后四位分别维护。

基础公司及存放位置由管理员维护、使用方读取；各自清单内唯一，被业务引用的记录不得删除。位置仍为72个固定层位，层位与取件码分别维护，展示时可以组合。更名后的历史展示、字段可见范围及脱敏方式列为待评审。

REQ-004申请按提交账号归属，学生只查询本人、工作人员查询全部、管理员只读查询全部；管理员不执行受理、寄出、取消及业务更正。各办理人账号引用同一账号格式，但按申请人、受理人、寄出人、取消人和更正人分别记录，不合并。公司引用基础维护清单，寄件手机号不替代账号归属。

REQ-003包裹按归属账号关联学生；待关联账号的包裹不向学生展示；变更绑定手机号不自动转移历史包裹归属，已完成业务保留原账号归属。包裹重复识别按“快递公司＋运单号”，不单独对运单号设全局唯一。自助取件由学生提交取件码与收件手机号后四位，系统核验通过后确认出库；收件手机号后四位仅用于本次核验，与完整收件手机号分别维护，默认不新增存储字段。快递公司、存放位置引用REQ-001基础维护清单，位置固定为A～L区、每区1～6层共72个层位，与取件码分别维护。拒收仅限待取件包裹；提交拒收后暂停取件，工作人员未开始退件时可撤回并恢复待取，退件开始后不能自行撤回，已完成退件不能恢复取件；同一包裹以当前有效的拒收请求为准，撤回后可再次提交。时刻统一UTC+08:00，JSON沿用带时区RFC3339，展示19字符不表示存储字节数。

REQ-003包裹待关联时允许缺失归属账号，不以空串、0或默认账号占位；已关联包裹及学生取件、拒收记录须有本人归属账号。取件码沿用调研报告第2部分的站内唯一要求，长度、字符范围及生成方式继续待评审。取件完成时间仅在核验通过并确认出库成功时必填，核验失败或未完成出库时不填；撤回结果仅在发起撤回且系统已返回处理结果时必填，未发起撤回时允许缺失，不等同于撤回失败。拒收申请编号识别请求，目标包裹通过所引用的快递公司与运单号共同识别，学生不重新录入这两项；不同公司下同号包裹分别关联。具体接口缺失表示及物理关联方式待设计。

提交、受理、寄出、取消及更正时刻分别对应成功事件；未发生时不填0或虚构时刻。时刻使用UTC+08:00，JSON沿用带时区的RFC3339，展示19字符不表示存储字节数。查询条件不持久保存，不提供表示不限定；null与空字符串、端点等细则待评审。已完成记录保留原内容，仅追加更正说明；流程08将已寄出和已取消列为完成记录。快照及派生值存储方式待设计。

必填缺失不以空串、0或默认账号填补；布尔假是有效值，不是缺失。接口层字段未提供/null/空字符串分别确认。字段是否完整返回、脱敏及复制原值要求按角色和具体场景评审，业务查询权限不自动等同全部字段可见。
