# 数据分析团队规范

## 范围与依据

数据分析描述业务需要哪些数据、含义、来源、使用方式和约束，是数据库设计与接口设计的输入。数据分析表不是数据库建表清单，一个表中列出的业务数据组不必对应一张数据库表。

开始前阅读[团队进度](../../management/team.md)、[全过程协作规范](../../standards.md)、[接口规范](../../api/README.md)、[数据库规范](../../design/database-design.md)及本模块已确认需求和业务流程。涉及对外字段时核对[OpenAPI](../../api/openapi.yaml)，尚未设计的接口与物理类型标注“待设计”。

## 文件与模板

- 各模块材料保存于本目录的`姓名_REQ-编号/`，课程提交使用教师数据分析XLSX模板，保留原有布局、栏目及说明。既有文件名不因本规范批量调整。
- 模板无法容纳的共享引用、约束、统计口径及待确认项放在同目录配套Markdown中，通过工作表名、数据组和数据项名称定位，不强行增加或删改模板列。
- 每份材料注明REQ、负责人、更新日期、依据文件及确认状态。新增数据项采用[统一编号](../../standards.md#统一编号与追踪)，既有项可在配套说明中补编号。
- 数据分析由各模块负责人完成，沈翔宇汇总；汇总不是简单拼接，须先检查共享定义及跨模块冲突。

## 数据项必须说明的内容

以下内容通过模板和配套说明合并表达，不能只填名称与类型。

| 内容 | 填写要求 |
| --- | --- |
| 编号与名称 | 稳定编号、统一中文名称；英文逻辑名确定后沿用camelCase，不提前冒充接口字段名 |
| 业务含义 | 数据表示什么、所属对象或业务场景；区分同名但含义不同的数据 |
| 来源与依据 | 对应需求、流程步骤及规则出处；说明用户输入、系统生成、引用还是计算所得 |
| 使用与维护 | 哪个模块维护、哪些模块读取、使用角色及何时允许更正 |
| 业务类型与格式 | 文本标识、文本、整数、日期、时刻等；格式、字符要求及大小写含义 |
| 长度、范围与单位 | 长度按字符还是字节、数值上下限、精度与单位；未确认时写待确认及影响，不任填固定长度 |
| 必填与缺失 | 哪个场景必填、何时允许缺失、默认值依据；区分未提供、null、空字符串和0 |
| 唯一及关联 | 唯一性适用范围、引用哪个对象、关联可否缺失及更正后的影响 |
| 取值及生命周期 | 字典来源、状态含义、产生或变更条件及负责模块；共享状态引用登记编号 |
| 输出与展示 | 哪些角色可见、是否允许完整返回、展示格式及复制是否保留原值 |
| 示例与确认 | 可公开的合成正例、反例及边界例；确认状态、评审人与未决问题 |

业务类型、JSON类型、Java/TypeScript类型及MySQL物理类型分层记录。已确认接口或存储设计的映射填入共享登记或配套说明，未确认的保持待设计；不能把模板中的“类型”直接当成四层类型均已定稿。

## 统一格式与语义

| 数据类别 | 团队要求 |
| --- | --- |
| ID、单号、手机号、取件码等标识 | 按标识语义处理，保留前导零；JSON使用字符串，长度和字符范围按对应需求确认。表格中的示例标识按文本保存，不能让Excel自动转数值或科学计数法 |
| 普通文本 | 明确长度、空白、大小写和输入规范化规则；未确认前不自行去除有业务意义的字符或改变大小写 |
| 数量及计算值 | 明确计数对象、范围、单位和精度，区分缺失与0；计数不因展示而转成带单位的接口字符串 |
| 日期与时刻 | 区分纯日期与具体时刻，记录对应业务事件和时区；JSON纯日期使用`YYYY-MM-DD`，时刻沿用接口规范的RFC3339及明确时区 |
| 必填与可空 | 场景分别说明，接口中使用`required`及`nullable`表达；修改操作中不传字段、传null、传空字符串的含义分别确定 |
| 状态及字典 | 中文含义、允许值、维护方及转换条件明确；展示名称、传输值与存储值有映射，不自行使用不同数字代号 |
| 引用数据 | 明确关联标识、当前值或历史快照的含义，确定维护位置；不通过复制另一模块的数据再各自修改来共享 |

上述规则沿用已有接口及数据库约定；尚未确认的具体字段名、长度、枚举和空值业务规则由对应条目评审确定。

## 跨模块数据核对

1. 新增数据项先检查其他模块和[共享登记](shared-data-dictionary.md)。同一业务事实复用编号、含义和约束；同名异义时改用准确名称，说明所属对象。
2. 原始业务数据由业务维护模块定义和维护，使用方补充读取需求。统计模块确定计算口径时须与来源模块共同核对，不另设一份可变业务记录。
3. 共享项在登记中明确维护方、使用方、来源、取值约束及确认状态；跨模块争议由杨振煜协调。登记后模块表保留模板需要的信息，并引用公共编号，后续变更一起同步。
4. 收件、自助取件、拒收和退件涉及的共用数据由任奕阳与张海睿核对；寄件数据及统计来源由沈翔宇与戴靖桓核对；账号、权限和基础信息的共享由杨振煜与使用方核对。
5. 已确认的取件码属于包裹核验场景，收件手机号后四位是核验输入；不能把完整手机号与后四位当成同一数据项，也不能据此默认新增独立存储字段。其他具体归属仍按实际需求核对。

## 统计数据的专门要求

每项指标说明名称、业务依据、计数对象、来源事件或数据、时间字段、时区、起止边界、筛选范围、去重方式、排除条件，以及撤回、更正和取消对结果的影响。区分“当前时点数量”与“期间发生数量”，不能只列名称和一个计算公式。

提供一组可手工核对的合成记录及预期值，覆盖边界时间和相关异常。合成例子用于解释口径，不是实际业务或测试已通过的证据。具体统计指标继续沿用已确认需求，不在本规范追加指标。

## 汇总与验收检查

- 数据项均有业务来源，覆盖对应流程的输入、输出和必要业务事实，未把界面装饰或未经确认的字段加入需求。
- 同一共享项的名称、格式、长度、必填条件、单位、唯一范围和允许值一致；存在差异时有合理场景说明及映射。
- 所有待确认项写明问题、影响、对接人及下一步，不以空白、“同上”或任意默认值掩盖缺口。
- XLSX可打开，原模板布局保留，标识示例未丢失前导零或被自动改写；配套说明能定位对应数据项。
- 维护方与受影响使用方完成核对并留下记录，沈翔宇汇总后再检查一遍；更新团队进度并说明尚未确认项。

本规范交付不表示各模块数据分析已汇总或评审通过。后续按实际材料逐项登记和确认。
