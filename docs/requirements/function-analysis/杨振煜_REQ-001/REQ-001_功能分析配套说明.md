## 角色、允许操作及数据范围

| 角色或场景 | 允许操作 | 数据范围与前置条件 |
| --- | --- | --- |
| 登录用户 | FUNC-001-01登录；FUNC-001-03修改密码 | 登录验证当前账号；修改密码仅限当前身份账号。强制改密完成前不开放业务功能 |
| 管理员 | FUNC-001-02建号并分配固定角色 | 全部待建立账号；账号格式与角色一致，账号和绑定手机号唯一 |
| 管理员 | FUNC-001-04密码重置、FUNC-001-05手机号变更 | 人工身份核对通过且存在的目标账号；失败保留原有效资料 |
| 管理员 | FUNC-001-06～11基础信息维护 | 全站公司及位置清单；名称唯一，已引用记录禁止删除；位置操作衔接P001-03 |
| 学生、工作人员 | 使用获准的公共登录和本人改密能力；在所属业务中读取基础信息 | 无账号创建、重置他人密码、绑定手机号变更或基础信息维护权限 |
| 各角色进入业务模块 | 按所属REQ检查角色、资源归属及当前业务条件 | 学生访问本人获准业务；工作人员办理收发、退件及条件允许的更正或取消；管理员只读查看全部业务和统计，不执行工作人员收发办理 |

管理员创建时选择学生、工作人员、管理员之一，一个账号对应一种固定角色。建号时角色分配已具备流程依据；存量账号后续角色变更的条件和对历史业务影响待设计。本次未添加角色增删、账号注销、启停、批量导入或自助注册功能。

## 处理结果及失败责任

账号、凭据及基础清单由REQ-001维护；账号归属及手机号更正产生的包裹关联操作由REQ-002维护，REQ-003消费实际包裹归属。手机号变更只更新账号绑定关系，不同时改写完整业务联系手机号、取件核验后四位或完成记录。

REQ-001校验、权限或保存失败时，返回失败并保留原有效资料；使用方不能以页面点击、输入校验通过或收到中间结果认定业务成功。公司、位置删除必须以处理时的有效引用情况判断；新增重复、修改重名、删除与业务引用同时发生的具体并发处理和错误契约在详细设计及接口评审中确定。

公司、位置更名保留既有业务关联，历史展示采用当前名称还是快照继续按P001-03确认。存放位置仍限制为A～L区、每区1～6层；现有流程07同时给出维护分支，新增是否仅补齐缺失层位、删除是否改变可用清单等具体规则尚待该条目评审，本次不选择实现方案。

登录、改密和重置中的密码原文仅用于当前校验或更新，不持久保存；仅保存密码哈希，算法及物理长度待设计。认证方案、登录态更新或失效、重试限制、会话退出等细则没有本次已确认设计，后续由P001-04及详细设计补齐。功能表中的提示文字用于表达可观察结果，不作为已登记接口message或业务错误码。
