## 四、本轮确认的规则

1. **归属按账号ID建立**：包裹与账号的归属关系保存账号ID（学生为学号），手机号只作为入库与更正时的匹配依据。账号绑定手机号变更不改变既有归属，与[调研报告](../../research/校园快递收发系统调研分析报告.docx)第2.3节一致，不需要修改该节。
2. **更正手机号触发重匹配**：工作人员在FUNC-002-04更正某条包裹的收件手机号后，按新号码重新匹配；匹配到其他账号时转移归属，原归属账号写入更正前内容快照。已完成记录（已取件、已退件）只追加更正说明、不转移归属，依据调研报告第4.4节。
3. **不设人工拒收核验**：拒收有效性由系统在学生提交时自动校验（本人包裹、尚未取走、线上提交），退回分支不成立。P002-04据此关闭，REQ-002不设"拒收核验"功能项；退件办理前的"核对包裹与拒收原因"作为FUNC-002-03的办理前置，不产生独立结论字段。
4. **退件发起与循环**：来源由学生拒收或人工异常入口确定，系统记录。开始时，学生拒收来源要求`拒收待退件`及当前有效申请，人工异常来源要求`待取件`，含待关联且可无拒收申请。继续和完成均以既有退件记录及`退件中`为条件，沿用原来源、关联包裹和开始时间；实际交接完成后登记`已退件`，重复提交保留原完成事实。
5. **退件原因组合**：来源为人工异常时禁止选择"学生拒收"；来源为学生拒收时默认"学生拒收"但允许按实际改选；原因为"其他"时说明必填。退回去向按现有两个取值填写，不新增第三取值。

## 七、验收要点

- **FUNC-002-01**：有效输入成功入库；同公司同号命中未办结记录时，无论确认为同一包裹或不同包裹都不新增；核对或更正后重新查重，重新入库追溯按P002-05确认；未关联仍入库且学生不可见；非法输入、资源缺失、越权时失败并保留已有记录。
- **FUNC-002-02**：手机号一致时建立账号ID归属并在FUNC-003-01可见；不一致、资源缺失、非待取件或已关联时失败；并发补关联只成功一次，原到站时间、取件码及入库事件保持。
- **FUNC-002-03**：分来源验收开始条件，人工异常可无拒收申请；退件中可继续同一记录，实际交接后登记完成；重复开始或完成不新增记录或计数；撤回与开始冲突按当前条件形成相容结果；来源篡改、原因非法、越权或资源缺失时失败。
- **FUNC-002-04**：合法更正有新值及原内容留痕；已完成记录及保存前刚完成的记录只允许追加说明；运单号命中未终态记录时拒绝保存；手机号更正后的有效归属、历史快照和可见性一致；输入、权限、资源及并发失败不覆盖有效业务结果。
- **FUNC-002-05**：工作人员和管理员按权限查询，管理员只读；首次使用、无记录或仅有入库无退件时允许合法查询，返回实际匹配项或空列表；起止颠倒、缺一端、关键词超长时失败；不存在详情返回相应提示；查询不改变业务数据。时间端点及字段可见性按原待评审事项确认后验收。
