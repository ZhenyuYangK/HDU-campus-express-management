## 角色、允许操作及数据范围

| 角色或场景 | 允许操作 | 数据范围与前置条件 |
| --- | --- | --- |
| 学生 | FUNC-003-01查询本人包裹；FUNC-003-02自助取件；FUNC-003-03提交拒收；FUNC-003-04撤回拒收 | 仅本人账号归属且获准办理的包裹；待关联账号的包裹不展示；变更绑定手机号不自动转移历史包裹归属 |
| 工作人员 | 不执行取件核验或出库确认 | 收件登记与退件办理归REQ-002；工作人员开始退件后学生不能自行撤回 |
| 管理员 | 只读查看全部业务与统计 | 不继承工作人员收发办理权限，不执行学生查询以外的业务办理 |
| 系统 | 执行取件核验、确认出库；记录拒收、暂停取件、撤回并恢复待取 | 按当前有效业务条件核验；任一条件不满足不完成出库或提交 |

学生仅办理本人账号归属的包裹，不能查看或办理他人及未关联的包裹；自助取件的核验与出库确认由系统执行，工作人员不参与。管理员只读查看全部业务与统计，不执行学生办理。待关联账号的包裹暂不向学生展示，由工作人员在账号建立或手机号纠正后补关联，归REQ-002办理。

## 处理结果及失败责任

包裹、取件记录和拒收申请由REQ-003维护；收件登记、退件办理及包裹待关联补关联由REQ-002维护，REQ-003消费实际包裹归属与状态；统计由REQ-005按成功事件读取。取件时间仅在核验通过并确认出库成功时记录，核验失败不产生取件时间。撤回结果仅在发起撤回且系统已返回处理结果时记录成功或失败；未发起撤回时无撤回结果，不等同于撤回失败。

REQ-003核验、权限或保存失败时，返回失败并保留原有效状态；使用方不能以页面点击、输入校验通过或收到中间结果认定业务成功。自助取件、拒收提交与撤回都按当前有效业务条件判断，重复取件、撤回与退件开始同时发生等并发情形的具体处理和错误契约在详细设计及接口评审中确定。

取件码沿用调研报告第2部分的站内唯一要求，长度、字符范围及生成方式待评审（P003-06）。收件手机号后四位仅用于本次核验，默认不新增持久存储字段，是否需要留存及重试、锁定策略待评审（P003-08）。包裹状态与拒收处理状态的传输值、存储值及跨模块衔接待评审（P003-07、P003-09）。功能表中的提示文字用于表达可观察结果，不作为已登记接口message或业务错误码。
