# 课程依据与交付清单

## 资料范围

本次核对资料：`task_source/`中的《软件工程课程设计PPT.pdf》（9页）与《范例及模版.zip》。用户确认通用模板适用于校园快递收发系统。原文件保留在本机，并由`.gitignore`排除；协作者需要原始模板时由组长单独提供。

- PDF第3页选定校园快递收发系统。
- PDF第4页规定4～5人组队、组长及角色分工；多个角色可由成员兼任。
- PDF第5页给出过程任务、提交格式和最低测试要求。
- PDF第5页要求第5～15周提交周报，共11周；具体日历日期以任课教师实际安排为准。
- PDF第7页给出评分：项目计划与执行监控25%、团队沟通及表现15%、课程设计作品45%、项目答辩15%。
- 压缩包包含需求分析、系统设计、系统测试、项目管理四类范例和模板，周报样例的项目名称为校园快递收发系统。样例中的张三、李四等均为示例，不能复制成真实团队信息。

## 交付映射

| 阶段 | 课程要求 | 提交格式 | 本项目目录 |
| --- | --- | --- | --- |
| 需求分析 | 所有业务流程图 | 图片放入DOCX | `docs/requirements/business-flows/` |
| 需求分析 | 数据分析表 | 按模板提交XLSX | `docs/requirements/data-analysis/` |
| 需求分析 | 功能分析表 | 按模板提交XLSX | `docs/requirements/function-analysis/` |
| 需求分析 | 每个功能项对应一张界面原型 | 原型图片放入DOCX | `docs/requirements/prototypes/` |
| 系统设计 | 模块结构图 | 图片放入DOCX | `docs/design/architecture/` |
| 数据库设计 | ER图、数据库表结构 | ER图放入DOCX；表结构按模板提交XLSX | `docs/design/database/` |
| 详细设计 | 至少两个模块的程序流程图、N-S图或PAD图 | 图片放入DOCX | `docs/design/detail/` |
| 系统实现 | 源代码 | ZIP | `backend/`、`frontend/`、`database/`，验收时打包 |
| 系统测试 | 至少两个模块；至少一个录入或编辑类型用例、一个查询类型用例；BUG清单 | 按模板提交XLSX | `docs/testing/cases/`、`docs/testing/bugs/` |
| 项目验收 | 每个功能模块至少一张运行截图、源代码介绍、团队分工、项目执行总结和每位成员的个人总结 | DOCX | `docs/acceptance/` |
| 项目管理 | 项目计划书 | DOCX | `docs/management/plans/` |
| 项目管理 | 每周进度、成员职责及集中讨论情况 | 按模板提交DOCX | `docs/management/weekly-reports/` |

压缩包中的数据库表设计参考及测试模板是旧版XLS，课件要求提交XLSX；填写和交付时需按课件格式另存，不得只改扩展名。

Markdown用于项目内协作、约定和记录，最终课程提交仍遵守上表规定的文件格式。

## 需求分析待完成项

现有材料没有给出完整的业务功能说明。需要从需求分析中确认：使用者和权限、收发业务流程、数据项和约束、功能清单、页面原型、业务状态及验收条件。确认结果应有需求编号并追踪到接口、设计与测试用例。

上述待确认项是分析检查项，不表示已新增具体业务功能。本次仅完成工程准备，不替代需求分析、详细设计、业务实现及课程验收材料。
